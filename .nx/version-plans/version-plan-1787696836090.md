`rateLimit` takes a list of limits, and a request is sent only when every one of them admits it — a vendor publishing "20 a second and 50,000 a day" is one client rather than two. The claim is a single backend operation, because claiming budgets in turn would leave the first spent whenever the second declined.

Templates can offer callers a closed menu of rate limits and let them pick one by key, for vendors whose quota depends on a subscription tier. A plan may be one limit or a whole tree keyed by sub-client path.

BREAKING: `rateLimit` no longer accepts a bare limit object — wrap it in a list. Budget keys move to `<client>:rateLimit:<limitName>`, so a rolling deploy would run two key layouts at once and can double the send rate; stop the fleet and restart it. `getClientStats().rateLimit` is now a list, one entry per declared limit.
